# 精密加工车间：生产流程与异常应对

项目基于 [RFTwin](https://github.com/WayneChou-bot/RFTwin) 开发，保留原应用及 MIT 许可。加工车间沿用其确定性时钟、事件记录、后端权威状态及隔离方案比较思路，新增机械加工订单、工艺路线、有限资源和对应的3D现场。

## 入口与启动

- `/workshop.html`：订单驱动的生产仿真，要求后端运行。
- `/workshop.html?mode=demo`：保留已确认的本地场景演示，不需要后端。
- `/`：原 RFTwin 应用和已有维修工单。
- 已确认的上一版场景保存在 Git 标签 `demo-baseline-v2`。

在仓库目录运行（先完成 README 所述依赖安装）：

```powershell
$env:Path = (Join-Path (Get-Location) '.venv\Scripts') + ';' + $env:Path
npm run dev:all
```

打开终端显示的前端地址，访问 `/workshop.html`。需要单独启动时，后端用 `.\.venv\Scripts\python.exe -m uvicorn apps.factory_backend.main:app --port 8000`，前端用 `npm --prefix frontend run dev`。后端端口改变时，前端启动前设置同样的 `TWIN_PORT`。

“仿真引擎已连接”表示本地软件仿真及其 WebSocket 快照连接正常，不代表接入真实设备。断线时保留最后画面并禁用生产操作，可重新连接或进入场景演示。

## 生产模型

初始暂停，三张订单共11件：ORD-001四件阶梯轴、ORD-002四件轴套、ORD-003三件阶梯轴；交期分别为生产开始后1100、800、1000仿真秒。订单设置可以改变零件类型、数量和交期，提交后重置共享生产状态。

- 阶梯轴：车削→铣削→去毛刺→清洗→尺寸检验→成品。
- 轴套：车削→去毛刺→清洗→尺寸检验→成品。
- L01/L02可加工两种零件，L03只配置轴类夹具；切换零件族计入8秒示例换型时间。
- R01服务L01/L02/L03，R02服务M01/M02/M03。每台机械臂同一时刻只服务一台机床，导轨移动及装卸消耗时间。
- 每个机床/工位输入缓存容量为2，包括已预留的在途工件；输出缓存容量也为2。下游占满会使上游无法继续卸料。
- 两台AMR承担实际转运任务。卸货后空载回到侧边待命点，再接下一单，车体不会停在机床边等待整个加工过程。
- RAW、FG和工位缓存有确定性的显示槽位，同一工件保留唯一ID和位置。CNC工件上下料由对应机械臂执行。

生产结果全部由后端推进。浏览器呈现快照，不再按独立时间表决定工件流转。初始工件没有加工完成事件之前不会自动前往下一工序。

## 建议演示流程

1. 点击“开始生产”，或用“推进60秒”观察有序转运、排队、换型和加工。暂停、倍速和重置对所有打开的生产窗口一致。
2. 点击左侧工件，镜头锁定该工件的实际位置；右侧显示所属订单、工序、位置、分配设备、等待原因和最近工序记录。点击订单可筛选工件。
3. 从“查看设备”选择L01，注入一个300秒故障。正在加工或上下料的工件留在原位，等待维修；受影响订单显示故障标记。故障结束或手动恢复后继续。
4. 点击“比较恢复方案”。系统先暂停，然后从同一快照比较FIFO等待、兼容机床改派、交期优先并改派。窗口可以调整，默认1800仿真秒。对比不会推进或修改当前生产。
5. 检查交付数、按期完成订单数、订单完工时间、总延期和累计工件等待。短窗口可能存在未完成订单，界面明确提示；此时延期数据只是窗口内已观察到的部分。
6. 点击“应用此策略”改变后续派工。待加工工件的改派需要AMR再次运输；已上机、换型中和加工中的工件不会直接跳到其他设备。过期快照不能应用，需要重新比较。

平面标签固定在场景中，选中对象位于画面中心；聚焦仍支持绕物件旋转与缩放。生产模式取消顶部梁架以方便看清内部，场景演示保留既有外观。

## 结果如何解释

本示例不预设“改派一定更好”。默认参数下，在仿真1秒时向L01注入300秒故障，从该状态前推1800秒，可复现以下结果：

| 策略 | 交付工件 | 最后一张订单交付时刻 | 按期完成订单 | 总延期 |
|---|---:|---:|---:|---:|
| FIFO等待维修 | 11 | 1191.2秒 | 0 | 446.4秒 |
| 兼容机床改派 | 11 | 1242.2秒 | 1 | 592.0秒 |
| 交期优先并改派 | 11 | 1000.2秒 | 3 | 0秒 |

总延期是各订单完工时刻超出交期部分之和；工件等待是所有工件等待时间之和。按期订单数与总延期可能朝不同方向变化。空车最终归位也计入场景运行时间，但不改变已经记录的订单交付时刻。比较窗口、故障时点、订单设置不同，结果会不同。故障还可能改变原FIFO任务顺序，偶然改善某些指标，不能据此推断故障有益。

机械臂利用率是该仿真中装卸/导轨服务时间占运行时间的比例。当前展示两台机械臂服务六台机床，并未证明这一数量适合真实工厂。

## 技术结构

- `packages/domain_machining/config.py`：严格校验订单和示例工艺参数。
- `engine.py`：复用原运行时的SimulationClock/EventBus，管理加工、缓存、机器人、AMR及事件；状态可JSON保存/恢复并计算hash。
- `comparison.py`：同一状态的三个独立策略分支。
- `apps/factory_backend/workshop.py`：`/api/workshop/`和`/ws/workshop`，输入/输出Pydantic模型、共享控制、版本校验；独立ticker不改原FactoryEngine语义。
- `frontend/src/workshop/`：沿用既有3D设备模型，增加生产状态连接、订单面板、工件追踪与比较界面。

生产REST包括snapshot/config/control/reset/fault/compare/apply。WS约5Hz发送全量快照；HTTP控制响应不能覆盖其他窗口重置后的新运行。启动配置与生产状态目前保存在内存，后端重启会重新初始化，不提供跨重启生产记录持久化。

## 演示边界

- 所有节拍、换型、维修、工艺与交期均为示例参数，无真实机床/PLC/MES数据，不控制设备，不计算刀路、材料去除、尺寸公差或质量概率。
- AMR采用预设通道，在出发前保守预留整趟任务经过的3米通道段（含空载返程）；重叠任务可能串行。这是可复现的物流约束，并非工业级调度或安全认证的避障规划。
- CNC上下料可见；料架槽位与交接点之间、固定后处理工位的取放机构采用瞬时简化，不提供完整机器人运动学或碰撞认证。
- 未完成订单的`projected_finish`为null。比较将状态前推后提供窗口内完成时间；实时面板不宣称具备经过校准的真实交期预测能力。
- 场景演示模式仍是独立视觉动画，其故障与工件回放不会联动；生产模式才由统一后端联动。
- 维修工单仍在原应用中，加工车间故障暂未自动创建该应用的维修工单。
