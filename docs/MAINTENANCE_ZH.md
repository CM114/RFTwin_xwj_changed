# 产线故障与维修工单：使用说明

本仓库基于 [RFTwin](https://github.com/WayneChou-bot/RFTwin) 开发，保留原有的 3D 产线、设备状态和仿真能力；新增维修工单、人员接单、处理记录、统计与维修时长方案对比。所有设备状态和比较结果均为软件仿真，不连接或控制真实设备。

## 本地启动

需要 Windows、Python 3.12、Node.js 和 Git。在项目根目录运行以下 PowerShell 命令：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm.cmd ci
npm.cmd --prefix frontend ci
$env:Path = (Join-Path (Get-Location) '.venv\Scripts') + ';' + $env:Path
npm.cmd run dev:all
```

浏览器打开 <http://localhost:5173>。首次启动时，后端需要预热仿真；界面顶部显示 `LIVE` 后才可使用工单和故障注入。这里的 `LIVE` 指本地仿真引擎正在运行，并不代表连接了实际工厂。如果显示 `LOCAL DEMO`，原有 3D 回放仍可查看，但无法创建或处理实时工单。

## 建议演示流程

1. 在 3D 工厂右侧的“注入”页选择 C-03 输送带卡堵；场景中的故障由原仿真引擎驱动。
2. 打开顶部的维修工单页面，查看自动生成的 C-03 工单和模拟故障时间。
3. 填写维修人员并接单；可以输入两种预计剩余维修时长进行对比。对比使用同一个仿真快照的两个副本，不会改变当前工厂。
4. 填写处理说明并完成工单；C-03 输送带通过仿真引擎的维修路径恢复，工单和统计随之更新。
5. 回到 3D 页面查看设备状态，或查看工单列表中的历史处理记录。

工单支持输送带卡堵、机械臂工具故障、AMR 故障和压缩机故障。完成当前输送带或机械臂工单时会尝试触发对应的模拟恢复；AMR 和压缩机仍按原引擎的计时规则恢复。工单记录会显示处理状态，设备是否恢复以仿真状态为准。机械臂工件的返工缓冲区已满时，恢复也可能需要等待。

维修时长和平均维修时长按**仿真时间**计算；暂停仿真时，时间不会前进。对比结果中的良品数量、停机时间和能耗为预测窗口内的增量。原项目的停机时间指标按瓶颈工序计算，不能简单理解为所有设备的停机时长之和。

## 数据与范围

- 工单默认保存在项目目录下的 `.data/workorders.sqlite3`，该目录不提交到 Git；可通过 `TWIN_WORKORDERS_DB` 指定其他数据库路径。
- 后端重启或重置仿真后，历史工单保留，但旧运行中的工单不能修改当前设备。不同后端进程使用独立的会话标识，避免运行编号重复造成误关联。
- 本地回放、断线或过期数据状态下不允许执行需要实时仿真引擎的工单操作。
- 仿真和工单属于演示用途；缺少真实设备接口、账号权限管理和生产环境所需的运维保障。
